# ADR-001: การเลือกใช้ Node.js และ Express.js เป็น Backend Framework

* **สถานะ**: อนุมัติแล้ว (Accepted)
* **วันที่ตัดสินใจ**: สัปดาห์ที่ 2
* **ผู้มีส่วนร่วมในการตัดสินใจ**: นายสุรวัจน์ ชลเรืองทรัพย์ (Tech Lead), นายสรวิชญ์ มีมาก (Backend Lead)
* **บริบทและปัญหา (Context)**: โครงการต้องการพัฒนาระบบร้านค้า E-Book ออนไลน์ที่มีทั้งส่วนการจัดการข้อมูลเชิงสัมพันธ์ (PostgreSQL), การประมวลผลคำสั่งซื้อพร้อมเพรียง, และการเชื่อมต่อไปยังบริการ AI ภายนอก จึงต้องการสภาพแวดล้อมฝั่งเซิร์ฟเวอร์ที่ทำงานแบบ Non-blocking I/O และมีโครงสร้างเรียบง่าย

---

## การตัดสินใจ (Decision)
ทีมตัดสินใจเลือกใช้ **Node.js (v20+ LTS)** ร่วมกับ **Express.js (v5.x)**

---

## ทางเลือกอื่นที่พิจารณา (Alternatives Considered)

1. **Python (FastAPI / Django)**:
   * *ข้อดี*: นิเวศน์เครื่องมือ AI แข็งแกร่ง
   * *เหตุผลที่ไม่เลือก*: Django ORM บดบังสถาปัตยกรรม SQL ดิบที่ต้องการแสดงในวิชาระบบฐานข้อมูล ส่วน FastAPI เพิ่มความซับซ้อนในการจัดการ Session และ Template เรนเดอร์หน้าร้าน
2. **Java (Spring Boot)**:
   * *ข้อดี*: แข็งแกร่งในระดับ Enterprise
   * *เหตุผลที่ไม่เลือก*: Boilerplate Code มีปริมาณมาก ใช้เวลาและทรัพยากรหน่วยความจำสูงเกินไปสำหรับโครงการขนาด 1 เทอม

---

## ผลลัพธ์และการประเมิน (Consequences)

* **ผลเชิงบวก**:
  * สมาชิกในทีมสามารถใช้ภาษา JavaScript ร่วมกันได้ทั้งฝั่ง Logic และ Template
  * การเชื่อมต่อแบบ Asynchronous กับ Neon Postgres และ AI API ทำได้อย่างราบรื่น
  * โค้ดมีขนาดกะทัดรัด ตรวจสอบและ Review ง่าย
* **ผลเชิงลบและความเสี่ยง**:
  * JavaScript เป็น Dynamic Typing อาจเกิด Runtime Type Error ได้หากขาดการเขียน Test ที่รัดกุม (แก้ไขโดยการวางชุด Unit Tests ครอบคลุมจุดเสี่ยง)
