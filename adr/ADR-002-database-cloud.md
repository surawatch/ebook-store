# ADR-002: การเลือกใช้ PostgreSQL บน Neon Serverless Cloud เป็นระบบจัดการฐานข้อมูล

* **สถานะ**: อนุมัติแล้ว (Accepted)
* **วันที่ตัดสินใจ**: สัปดาห์ที่ 3
* **ผู้มีส่วนร่วมในการตัดสินใจ**: นายสุรวัจน์ ชลเรืองทรัพย์ (Architect), นายสรวิชญ์ มีมาก (Backend Lead)
* **บริบทและปัญหา (Context)**: ระบบต้องการฐานข้อมูลเชิงสัมพันธ์ที่รองรับทฤษฎีการจัดรูปแบบบรรทัดฐาน (3NF), สามารถทำ ACID Transaction ควบคุมคำสั่งซื้อหลายตารางพร้อมกัน, และพร้อมเข้าถึงได้ผ่านอินเทอร์เน็ตโดยไม่ต้องตั้งเซิร์ฟเวอร์ฐานข้อมูล Local บนเครื่องของสมาชิกแต่ละคน

---

## การตัดสินใจ (Decision)
ทีมตัดสินใจเลือกใช้ **PostgreSQL บน Neon Serverless Cloud Platform** ผ่านไลบรารี `pg` (Node-Postgres Connection Pool)

---

## ทางเลือกอื่นที่พิจารณา (Alternatives Considered)

1. **Local MySQL / SQLite**:
   * *ข้อดี*: ติดตั้งง่ายบนเครื่อง
   * *เหตุผลที่ไม่เลือก*: ไม่สามารถเชื่อมต่อข้ามเครื่องระหว่างเพื่อนในกลุ่มและกรรมการตรวจงานได้ อีกทั้ง SQLite ขาดฟังก์ชันด้าน User Concurrency และ Timezone สำหรับภาษาไทยที่เข้มงวด
2. **MongoDB (NoSQL)**:
   * *ข้อดี*: คล่องตัว ไม่มี Schema ตายตัว
   * *เหตุผลที่ไม่เลือก*: ขัดแย้งกับหลักการเรียนรู้ Relational Integrity, Foreign Keys, Referential Actions (`ON DELETE RESTRICT`) และการทำ Normalization ในวิชาระบบฐานข้อมูล

---

## ผลลัพธ์และการประเมิน (Consequences)

* **ผลเชิงบวก**:
  * ข้อมูลทั้ง 9 ตารางถูกเก็บศูนย์กลางบนคลาวด์ สมาชิกทุกคนเข้าถึงข้อมูลจริงชุดเดียวกัน
  * ระบบมีฟีเจอร์ Database Branching เหมาะสำหรับการแยกฐานข้อมูลสำหรับทดสอบ (Test DB)
  * รองรับชนิดข้อมูล `TIMESTAMPTZ` สำหรับการคำนวณยอดขายข้าม Timezone
* **ผลเชิงลบและความเสี่ยง**:
  * แผนฟรีของ Neon มีการ Sleep (Cold Start) ราว 2-3 วินาที เมื่อไม่มีคำขอเข้ามานาน (แก้ไขโดยแจ้งเตือนในเอกสารการตรวจงาน และออกแบบ Client ให้รอได้อย่างเหมาะสม)
