# ⚖️ การทบทวนด้านจริยธรรมและความปลอดภัย (Ethics & Safety Review)

**โครงงาน**: ระบบร้านขายหนังสือและอีบุ๊กออนไลน์ (E-Book Store Online Management System)  
**วิชา**: วิศวกรรมซอฟต์แวร์ในยุค AI (Software Engineering in AI Era)  
**มาตรฐานอ้างอิง**: AI Ethics Framework 5 คำถาม & 10-Item Checklist (บทที่ 14 §14.4.13), พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA)

---

## 1. การตอบ 5 คำถามจริยธรรมหลัก (The 5 Ethical Questions - บทที่ 14 §14.4.13)

### คำถามที่ 1: Context & Stakeholders (บริบทและกลุ่มผู้มีส่วนได้ส่วนเสียคือใคร มีกลุ่มเปราะบางหรือไม่?)
* **บริบทของระบบ**: ระบบจัดจำหน่ายหนังสือและสื่อการเรียนรู้ดิจิทัล โดยมีผู้ใช้งานเป็นนักเรียน นักศึกษา บุคลากรสายเทคโนโลยี และประชาชนทั่วไปที่ต้องการพัฒนาตนเอง
* **กลุ่มเปราะบาง (Vulnerable Stakeholders)**: 
  1. *นักเรียน/เยาวชน*: อาจไม่มีบัตรเครดิตหรือความรู้เรื่องความปลอดภัยทางไซเบอร์ จึงต้องมีระบบจำลองการชำระเงินที่ปลอดภัย ไม่หลอกล่อให้เสียเงินจริง
  2. *ผู้เขียน / เจ้าของลิขสิทธิ์หนังสือ*: หากระบบมีช่องโหว่ให้ดาวน์โหลดไฟล์ได้ฟรีโดยไม่จ่ายเงิน ผลงานของนักเขียนจะถูกละเมิดลิขสิทธิ์
* **มาตรการบรรเทาผลกระทบ (Mitigation)**:
  * บังคับใช้กลไก Access Control ที่ระดับ SQL Query เพื่อป้องกันการลักลอบดาวน์โหลด (Anti-IDOR)
  * ไม่แสดงข้อมูลส่วนบุคคลของผู้ใช้คนอื่นในหน้าจอสาธารณะ

### คำถามที่ 2: Data & Privacy (ข้อมูลที่ใช้มีที่มาอย่างไร และจัดการเรื่องความเป็นส่วนตัวตาม PDPA อย่างไร?)
* **การเก็บรวบรวมข้อมูล**: ระบบจัดเก็บเพียง `username`, `email`, และ `full_name` เพื่อใช้ในการระบุตัวตนและจัดส่งลิงก์ดาวน์โหลดเท่านั้น ไม่มีการเก็บข้อมูลบัตรเครดิต เลขประจำตัวประชาชน หรือข้อมูลสุขภาพ
* **ความสอดคล้องกับ PDPA**:
  * *ฐานสัญญา (Contractual Basis - มาตรา 24(3))*: การเก็บอีเมลและชื่อเป็นสิ่งจำเป็นต่อการปฏิบัติตามสัญญาการซื้อขายและส่งมอบสินค้าดิจิทัล
  * *การโอนข้อมูลข้ามพรมแดน (Cross-border Data Transfer - มาตรา 28/29)*: ข้อมูลที่ส่งไปยัง Google Gemini API มีเพียงคำค้นหา (Query) และข้อมูลแคตตาล็อกหนังสือในร้านเท่านั้น **ไม่มีการส่งข้อมูลส่วนตัว (PII) เช่น ชื่อหรืออีเมลของลูกค้าไปยัง AI ภายนอกเด็ดขาด**

### คำถามที่ 3: Autonomy & Agency (มนุษย์ยังคงมีอำนาจควบคุมและตัดสินใจสุดท้ายหรือไม่?)
* **Human-in-the-loop**:
  * ระบบ AI ทำหน้าที่เพียง "ผู้ช่วยแนะนำหนังสือ (Advisor / Recommender)" เท่านั้น ไม่สามารถสั่งซื้อสินค้าหรือตัดเงินแทนผู้ใช้ได้โดยอัตโนมัติ
  * ผู้ดูแลระบบ (Human Admin) เป็นผู้ตรวจสอบสลิปและกดอนุมัติคำสั่งซื้อด้วยตนเอง ไม่มีการใช้อัลกอริทึมอัตโนมัติในการระงับบัญชีผู้ใช้โดยปราศจากการตรวจสอบของมนุษย์
  * ผู้ใช้มีอิสระ 100% ในการเลือกซื้อหรือไม่ซื้อหนังสือตามที่ AI แนะนำ

### คำถามที่ 4: Fairness & Bias (ระบบสร้างความไม่เป็นธรรม หรือมีอคติในการแนะนำหรือไม่?)
* **การป้องกันความลำเอียง**:
  * ระบบ AI ถูกกำกับใน System Prompt ให้แนะนำหนังสือตาม "ความต้องการและเนื้อหาทางวิชาการ" เป็นหลัก ไม่มีการจัดลำดับผลลัพธ์โดยแอบแฝงค่าคอมมิชชัน หรือลำเอียงแนะนำเฉพาะหนังสือราคาสูง
  * มีการตรวจสอบผลการทดสอบในชุด Eval (TC-EVAL-09) เพื่อให้แน่ใจว่าผู้ใช้ที่มีข้อจำกัดด้านงบประมาณยังคงได้รับคำแนะนำหนังสือราคาประหยัดอย่างเท่าเทียม

### คำถามที่ 5: Transparency & Accountability (ระบบมีความโปร่งใส และใครเป็นผู้รับผิดชอบเมื่อเกิดความผิดพลาด?)
* **ความโปร่งใส (Explainability)**:
  * ระบบระบุอย่างชัดเจนบนหน้าจอว่า *"ผลลัพธ์นี้ประมวลผลโดยปัญญาประดิษฐ์"* และแสดงเหตุผลสั้น ๆ เสมอว่าทำไมจึงแนะนำเล่มดังกล่าว
  * กรณีที่เข้าสู่โหมดสำรอง ระบบแสดงป้ายเตือน *"Fallback Mode (ระบบสำรอง)"* อย่างตรงไปตรงมา
* **ความรับผิดชอบ (Accountability)**:
  * ทีมผู้พัฒนา (นายสุรวัจน์ ชลเรืองทรัพย์ และ นายสรวิชญ์ มีมาก) รับผิดชอบต่อความถูกต้องของระบบและความปลอดภัยของข้อมูลทั้งหมด ตามหลักการวิชาชีพวิศวกรซอฟต์แวร์

## 2. รายการตรวจสอบ 10 ข้อก่อนการปล่อยระบบ (10-Item Ethics & Safety Checklist)

| ข้อที่ | รายการตรวจสอบ (Checklist Item) | ผลการตรวจ | หลักฐานเชิงประจักษ์ (Evidence / Action Taken) |
| :---: | :--- | :---: | :--- |
| **1** | **No PII Leaks to AI**<br>ไม่ส่งข้อมูลส่วนบุคคลของลูกค้าไปยังโมเดล AI ภายนอก | ✅ ผ่าน | ตรวจสอบใน `services/aiService.js` พบว่าส่งเฉพาะคำค้นหาของผู้ใช้กับแคตตาล็อกหนังสือเท่านั้น |
| **2** | **Zero False Attribution**<br>ไม่กุชื่อหนังสือ ผู้แต่ง หรือราคาปลอมขึ้นมาหลอกลูกค้า | ✅ ผ่าน | มี Catalog ID Whitelist Filter กรองหนังสือที่ไม่มีจริงในร้านออก 100% ในโค้ด |
| **3** | **Anti-IDOR Access Control**<br>ป้องกันผู้ใช้เข้าถึงไฟล์หรือคำสั่งซื้อของผู้อื่น | ✅ ผ่าน | ฟังก์ชัน `getDownloadLinks` และ SQL ใน `/download/:id` บังคับเช็ค `user_id` และสถานะ `confirmed` |
| **4** | **Graceful Degradation**<br>ระบบไม่ล่มเมื่อเครือข่าย AI ขัดข้อง | ✅ ผ่าน | มี Rule-based Fallback สลับไปแนะนำหนังสือตามหมวดหมู่อัตโนมัติ |
| **5** | **No Hidden Fees / Sneaky Checkout**<br>ไม่ยัดสินค้าอื่นลงตะกร้าโดยที่ผู้ใช้ไม่ได้กด | ✅ ผ่าน | ตะกร้าสินค้าเพิ่มเฉพาะเล่มที่ผู้ใช้กด "เพิ่มลงตะกร้า" ชัดเจนเท่านั้น |
| **6** | **Historical Price Integrity**<br>บันทึกราคาซื้อขายประวัติศาสตร์อย่างถาวร | ✅ ผ่าน | ตาราง `order_items` มีฟิลด์ `price_at_purchase` เพื่อป้องกันยอดขายย้อนหลังเพี้ยน |
| **7** | **Thai Character Encoding**<br>รายงานภาษาไทยต้องไม่เป็นภาษาต่างดาว | ✅ ผ่าน | ฝังรหัส UTF-8 BOM (`\uFEFF`) ในการ Export CSV ทุกรายงาน |
| **8** | **Secret Key Protection**<br>ไม่มี Connection String หรือ API Key ค้างใน Git | ✅ ผ่าน | แยกตัวแปรความลับไว้ใน Environment Variables บน Vercel และเพิ่มใน `.gitignore` |
| **9** | **Prompt Injection Resistance**<br>รับมือกับข้อความสั่งขโมยข้อมูลหรือลบตารางได้ | ✅ ผ่าน | ผ่านชุดทดสอบ Adversarial Cases ใน Golden Dataset (TC-EVAL-21 ถึง 25) |
| **10** | **Academic & Engineering Integrity**<br>เปิดเผยการใช้งาน AI ในการพัฒนาอย่างโปร่งใส | ✅ ผ่าน | บันทึกรายละเอียดครบถ้วนใน `AI_USE_LOG.md` และระบุเหตุผลข้อเสนอที่ปฏิเสธ |

## 3. สิ่งที่ทีมตัดสินใจ "ไม่ทำ" เพราะการพิจารณาทางจริยธรรม (Rejected Features)

1. **ไม่ทำระบบแอบเก็บประวัติการคลิกแบบเจาะจงบุคคล (No Invasive Tracking)**:
   * AI แนะนำให้เก็บพิกัด GPS และประวัติการเลื่อนหน้าจอของลูกค้าเพื่อนำมาเทรนโมเดล แต่ทีม **ปฏิเสธ** เพราะเป็นการละเมิดความเป็นส่วนตัวเกินความจำเป็นของร้านหนังสือ
2. **ไม่ใช้ AI ในการตัดสินใจเรื่องเงินและสถานะคำสั่งซื้อโดยอัตโนมัติ**:
   * แม้จะมีโมเดลสแกนสลิปโอนเงิน แต่ทีมตัดสินใจให้ผู้ดูแลระบบเป็นผู้อนุมัติขั้นสุดท้าย (Human-in-the-loop) เพื่อป้องกันข้อผิดพลาดจากการตัดยอดเงินผิดพลาด
3. **ไม่แสดงหนังสือที่มีเนื้อหาอันตรายหรือสร้างความเกลียดชัง**:
   * ระบบบล็อกคำขอแนะนำหนังสือเกี่ยวกับการสร้างมัลแวร์หรืออาวุธ (TC-EVAL-22) โดยคืนผลลัพธ์ว่างอย่างปลอดภัย
